> 一段获奖发言，252 秒。
>
> 不到六百字。
>
> 零个感叹号。

后来，它被拆成了一个 <code>.skill</code> 文件。

文件里没有奖杯。

只有写法。

<code>feitian-speech</code> 从第 35 届飞天奖的一段获奖发言里，拆出一套致辞写法：一个比喻从中段走到结尾，感谢有快有慢，荣誉一层一层让出去，最后落在一句朴素的承诺上。

装上以后，模型不会替你拿奖。

它只是不再写“感谢所有帮助过我的人”。

## 先看一段

普通模型写获奖感言：

> 非常荣幸获得这个奖项，感谢所有帮助过我的人，感谢这个伟大的时代。这是一个新的起点，我会继续努力，不忘初心，砥砺前行。

一个具体的人也没有。

飞天致辞写法（虚构场景：一个 42 岁从零学 AI 的人拿了新人奖）：

> 还要特别特别感谢周老师。
>
> 从我装上第一个 Claude Code，到今天能自己写出一个 skill，
>
> 是您一遍遍地回我消息，一遍遍地看我那些看不懂的报错截图。
>
> ……
>
> 这座奖杯，在我看来是一个光标。
>
> 它没有停，它还在闪。

一个人，一件事，一个比喻。

## 两个入口

| 入口 | 什么时候用 | 怎么写 |
| :--- | :--- | :--- |
| **A 获奖感言** | 领奖、颁奖、答谢、毕业、退休、开业 | 先敬同场，荣誉外让，快速感谢，恩师位放慢，主比喻收尾 |
| **B 年会总结** | 年会上台讲这一年 | 给这一年定性，回顾两三件事，每件落到一个人身上，再感谢、收束 |

说清了场合就会自动走对应的入口。说不清，它会先问一句。

## 它的几条规矩

> 全篇只养一个比喻，让它回来至少三次。
>
> 感谢只给一个人放慢，其余一句一个。
>
> 每个大词后面，跟一个能做出来的动作。

还有一条：**不编名字。**

材料里没有的人名、作品名、数字，它留 <code>【待补】</code>。致辞是要当着人念的，念错一个名字，比写不好更麻烦。

## 安装

把这句话发给支持 Skills 的 Agent（Claude Code、Codex 等）：

~~~text
帮我安装这个 skill：https://github.com/xub5266-web/feitian-speech
~~~

或者把仓库里的 <code>feitian-speech</code> 文件夹整个复制到本机的 Skills 目录：

~~~text
Claude Code：~/.claude/skills/feitian-speech/
Codex：      ~/.agents/skills/feitian-speech/
~~~

也可以下载 <code>dist/feitian-speech.skill</code> 安装包。

## 使用

直接说：

~~~text
用飞天致辞帮我写个年会总结发言，3 分钟。
~~~

它会把缺的材料一次问完。想省一轮，就复制下面的卡片填空。

**入口 A：获奖感言**

~~~text
用飞天致辞写获奖感言：
1. 场合：
2. 时长：
3. 凭什么得奖（带名字）：
4. 最想感谢的一个人 + TA做过的一件事：
5. 其他要感谢的：
6. 一句干这行的大白话（可不填）：
~~~

**入口 B：年会总结**

~~~text
用飞天致辞写年会总结发言：
1. 我的身份（负责人/员工代表）：
2. 时长：
3. 今年最值得讲的两三件事（带数字或名字）：
4. 每件事是谁在做：
5. 最该单独谢的一个人 + TA做过的一件事：
6. 其他要感谢的：
~~~

A 必填第 3、4 项，B 必填第 3、4、5 项。

它适合：

- 要上台念的稿子，一到五分钟
- 想体面，又不想空
- 有具体的人可以感谢

这些先不要：

- 吐槽、脱口秀、需要抖包袱的场合
- 交给领导看的书面述职报告
- 一个具体的人名、一件具体的事都给不出来

## 先把关系说清楚

这个项目是独立的写作技法研究，与王仁君本人、飞天奖及相关机构没有关联，也不代表任何相关方的立场。参考文件只摘了原发言的少量片段，用来拆解手法。

## 反馈

模型有时会复发。

它会在最该说一个人名的地方写：

> 感谢一路走来所有关心和帮助过我的人。

看到这句，欢迎提 Issue。最好附上你填的材料、使用的模型，和它写出来的那一段。
